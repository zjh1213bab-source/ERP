# 跳色科技 ERP 系统

> 面向 100-500 人服装外贸一体化企业的 ERP：**下单（多色/尺码/美金）→ 开发单/技术确认 → 财务成本审核 → 分单 → 生产工序/报工 → 成品入库 → 库存调拨 → 美仓发货 → 报表/打印** 全链路已闭环，可直接本地/局域网运行，也可部署到服务器。

## 一、功能总览

| 域 | 能力 |
|---|---|
| 账号权限 | JWT 登录、7 角色 RBAC（管理员/销售/技术/财务/生产/仓储/只读）、用户与角色管理页、**按钮级权限（can 权限表）** |
| 工作台 | 本月订单/金额、在产、待审批、逾期与缺货提醒、**近 7 日订单趋势**、状态分布、最近订单 |
| **字段级脱敏与访问审计** | 身份证、手机号、工资、合同金额在**服务端返回时就已经是掩码**（不是前端隐藏，开发者工具也看不到明文）。**管理员的技术权限不默认可读工资** —— 判定用角色基础权限而不是 `hasPerm`（后者 admin 恒通过，等于白做）；想看明文走「一次性查看」，必须写理由、每次留痕。权限点按「谁真的需要」拆细：`hr.pii` / `crm.pii` / `supplier.pii` / `payroll.sensitive` / `contract.sensitive`。**导出也脱敏并留痕**；工资/合同类的「留痕」开关服务端强制为开。日志区分「有权限」与「申请查看」 |
| **办公耗材与服务采购** | 办公用品有**自己的仓与流水**，和生产材料仓、成品仓完全分开 —— 领一箱 A4 纸不会从面料库存里扣（共用一张表的后果是「面料库存里出现 A4 纸 -5 包」，齐套算料把它算成缺料）。申领走三道闸：库存不足拦、同人同物品未结拦、**超部门月限额要写例外说明**才放行；审批可砍量，**出库才真正扣库存**。多张已批准申领可**合并成一张采购单**（同一物品自动汇总），来源可追溯、不能被两张在途单同时占用。**验收一次做完三件事**：耗材入库、**耐用品逐件建资产卡（一物一码，金额不进费用）**、耗材+服务生成一条行政支出并**占用部门预算** —— 验收与费用同源，不用行政再手工录一遍；耐用品转资产后不再当耗材重复费用化。**最低库存只提示不自动下单**（自动补货等于在没人核价的项目上自动花钱） |
| **售后与对账资料** | 客户在商城自助提售后（**质量问题/错款/破损必须带照片**，否则业务只能凭一句话去和工厂吵），业务受理后**五条轨道各自独立**推进：退款 / 实物实收 / 质量检验 / 再上架 / 追偿。**退款不直接恢复库存**（原型原话）—— 退钱只动钱，良品只有经仓库逐件判定并指定可售库位后才进可售；实物三轨**不存副本**，从关联退货单实时算（存副本必然出现「售后页待判定、仓库页已判定」）。金额三道闸：索赔 ≤ 行货款（手滑多打一个零不该变成巨额退款）、退款 ≤ 索赔、追偿 ≤ 赔款。结案三前提：实物已关单 / 已退款 / 结论 ≥8 字。对账资料走**定版快照 + 授权发布**：草稿不对外、check_diff≠0 不许发（说明有发票被手工改过）、撤销立即失效、每次下载留痕；CSV 带 BOM 与中文文件名 |
| **客户进度发布** | 客户想知道「我的货做到哪了」不再只能打电话。三条路线（**本厂 / 裁片外发 / 整单外发**）各自的阶段不同，路线自动推断（有外发记录就是裁片外发），人工改过就不再被覆盖。**客户只看业务主动发布过的快照**，不直连内部表 —— 快照能复现、也天然挡住内部字段：不含外发厂名、加工单价、返工数、工人姓名、内部备注。**最硬一条：外发没全部回货、回厂后整与终检没做完，客户快照里连「完工 / 可发货」字段都不出现**（不是显示灰色未完工，是根本没有）。**撤回不删行**：状态转已撤回 + 版本号 +1，历史可查；同一订单同时只有一个生效版本。发布前会挡两类自相矛盾：路线是外发但没有外发记录、外发未开始却已有后整/检验进度 |
| **员工自助与薪资申诉** | 员工登录只看自己的：本月出勤/迟到、已休假期、**工资条明细**、技能到期、我的申请。**范围由「账号 ↔ 员工档案」绑定决定，不按姓名猜** —— 未绑定账号只能看到「请联系人事绑定」（库里 10 个账号没有一个能对上员工档案，按名字猜会把 A 的工资发给 B）。**只有已确认/已发放的工资单可见**（核算中的不给看，看了又改只会制造申诉）；**申诉 30 天窗口**、同一张工资单只许一条处理中。**批准不改已付历史**：申诉批准生成「下期生效」的调整单，原期金额/状态/时间都不动。补卡批准会真的写考勤（状态与考勤模块同口径 `normal`）、资料更正只能改手机号与紧急联系人。主管只看天数，**不含金额、不含请假类型**（病假属敏感）。本人看自己的工资条也留痕（`granted=1`） |
| **技能矩阵与岗位资格** | 排程原来只知道「这个工作中心有 12 小时产能」，不知道「有没有人能上这道工序」。现在给出**人 × 工序矩阵**（谁会什么、几级、什么时候到期）、**覆盖缺口**（每道工序合格几人 / 需要几人 / 缺口，另列「排程用到但没建门槛的工序」）、**到期清单**（技能复评 / 证书 / 复训三合一）。**等级只来自考核评定**，报工只作「做过」的证据回填 —— 干得多不等于干得好，所以只有评定且达标的才算可独立上岗。**受限工序没资格不许报工**（门禁挂在报工接口上，不是只给一个查询）；破格放行必须写理由 + 有期限 + 进覆盖清单。**查不到人不拦报工**，只计入「未归属」去补档案。本模块**不扣款、不参与打分**（原型：AI 不能自动打低分裁员） |
| **流程变更与发布审计** | 审批流是**制度**不是代码：改流程走变更单，四步链路 **创建 → 试运行 → 发布 → 回滚**。**没有试运行证据不许发布**（拿近 90 天历史单逐单对比审批路径，出前后对照）；**生效日不能倒签**（不能今天发布、生效日写上周）；**在途单默认不随改版变形**（发单时记 `flow_version_id` + `steps_snapshot`；要迁移必须显式选且只迁「一步都没开始」的，已批过一半的迁移会打回起点）；**删关键角色必须写理由**（财务/总经理从流程消失时试运行单独列出）—— 这就是「关键门槛不允许因加急被绕过」的落地；全过程审计留痕、可回滚 |
| **异常协同与日清** | 把散在各模块的异常**扫**成一张「今日必办」（技术/缺料/质量/产能/人事/资金六类 + 流程审批）：11 条规则直接读业务表判定事实，不靠人工上报；**日清只收升级事项**（严重级 / 超 SLA 没人认领 / 过了预计解决日），不是把所有待办重列一遍；每条带**原单链接、影响金额、归口部门、责任人**，可认领 / 转派 / 关闭 / 复核。**同一事实只占一条**（幂等键 = 主体+规则+原单+区分键，只约束未关闭），同一天扫 10 次不重复派单；**「事实消失」与「人处理完了」分开记**（`auto_resolved` 不算人工完成，事实再出现时恢复原条目而不是新建）；**缺数据写进覆盖率**（12 张订单没填交期就说 12 张，不显示「超期 0 单」；没有规则的类别明说「需人工排查」）；**能清零**（历史遗留可标 `ignored`，必须写理由、可设到期日、被压住的条数在扫描结果里可见）；**只写清单**，不改单据、不扣绩效、不扣工资 |
| **生产交付效率与质量报表** | 固定八项：准交率 / 延期原因 / 工序效率 / 一次合格率 / 返工报废率 / 在制龄 / 材料利用 / 计划实际差异。**第一原则是算不出来就说算不出来**——每个指标都带分母（5/7 还是 500/700），样本 < 5 只给数字不给比率，分母为 0 显示「—」不显示 0%，缺数据单列覆盖率清单（7 条）。**准交双口径并列**（按承诺日到期 vs 按实际发运）且**与工厂段达成不相减**（剔掉下单前等待再叫准交率是化妆）；**工序产出不相加成整件产量**（裁 220 + 车缝 3245 ≠ 产量，整件只认订单件数）；**返工复验合格不再算一次合格**；**材料利用率不计算**并写明缺净用布面积；**交期四段下钻**（技术制版 / 销售接收 / 资料接收 / 在制变更），没源事件显示「—」不填 0 天 |
| 主数据 | 客户、产品、面辅料库（面料/辅料）、尺码模板 |
| 销售订单 | 一款多颜色、按色按码数量与**美金单价**、后台可设汇率并快照、款名/客户订单号/跟单员/店铺信息/交货方式/贸易条款/包装要求、订单导出 Excel |

| 分厂执行 | 工厂/外协主数据、订单分单（本厂/外协，可多次拆分；首次分单推进到「已分单」）、**外协对账与结算** |
| 工艺与用量 | 工艺明细（倍率/FOB/外发/洗水/裁剪）、面辅料用量（单件用量/损耗/总用量/金额，可带入成本） |
| 生产 | 13 道标准工序、状态/计划/实际/责任人、报工明细（合格/不良/工时）+ 累计、生产看板（进度/当前工序/逾期）；**接单评审与交期承诺**（T0 起算 + 三项承接确认 + 督办点）→ **齐套与缺料**（需求→库存→在途→净缺口）→ **裁床排料与扎包**（缸号/层数/裁差校验）→ **首件确认与工位工艺**（按冻结版测尺寸验工艺，未放行不许报工） |
| **质量与合规** | 质量标准与检验计划（来料/过程/成品/童装合规，含致命项与 AQL）· 检验单录入与判定 · **不合格自动开异常单**（返修/报废/让步）· **批次追溯**（订单→检验→异常→召回→出入库）· 童装合规资料 · **召回评估与客户通知** |
| 库存发货 | 生产仓+美仓台账/流水/调整/调拨、按订单入库与发货（库存校验）、**缺货一键补货**、**美仓发货核对视角** |
| 采购 | 面辅料采购单（草稿→下单→**到货点收生成收料单**，供方必须选档案）；**供应商评价与备用产能**（样本取自收料单 → 四维打分 → 样本不足不排名 → 整改闭环 → 备用三项验证 → 资格卡住下单）；**停单改量退料**（客户改单 → 减量只动未交 + 供方确认 → 整单停单要有到货先退料 → 退料实物/贷项双回执）；**返工报废与生产结单**（返工必复验、报废必填损失、批准人≠制单人，损失自动进成本 rework 层；结单五项检查，部分关闭要争议挂账）；**设备停机与产能**（设备台账 → 停机登记即扣可承诺产能 → 维修 → 安全复核人工放行 → 产能日历按工作中心算可用台时与损失）；**原料收货检验**：卷号/缸号/库位可追，实收进「待检」，来料检查合格才进可用库存，超收/短收按原单调查，退回回退采购行等补发 |

| **长期投资抵消** | **合并表最容易出错的一块**：母公司账上的「长期股权投资」和子公司账上的「实收资本」是同一笔钱的两种记法，直接相加就把同一块钱算两次。**只有子公司才抵**（独立法人、有股权），**分公司直接并入不抵消**——这条搞错会让资产与权益同时虚增，且合并表还能「平」，因为那是两边一起虚增的假平衡。长投账面 ↔ 子公司权益全额对冲，差额是**商誉**（不摊销、每年减值测试）或**负商誉**（计入营业外收入并附注披露），非全资按 `权益 × 少数股东比例` 确认**少数股东权益**。**成本法**账面只认投资成本、分红只确认投资收益不冲账面；**权益法**账面随子公司损益调整，**亏损以账面减至 0 为限**，超出部分是未确认投资损失只能账外备查，**绝不允许长投变负数**。抵消分录**借贷必须相等**，不等直接不出这张合并表；且因 `商誉 = 长投 − 权益×持股比例` 恒成立，抵消对资产与权益的净影响必然相等，所以合并后「资产 = 负债 + 权益」仍是**真平衡**。持股增减、分红、损益确认逐笔留痕，账面价值可回溯 |

| **计件工资** | 车间最普遍的薪资形式是计件，但工钱一直靠组长的小本子。这一页把报工数据接上工价表：**只算合格数**（不良不付）、**超报按扎件数封顶**（同扎同工序累计不可能超过件数，超出部分是报工错了，逐笔列出来核对）、**缺单价绝不按 0 算**（草案可存、确认直接拒）、**归人三级且认不出就不猜**（`employee_id` > 姓名唯一匹配 > 无法归属，重名/临时工进清单）。单价**按生效日版本化**：今天调价不改上个月已算过的钱；已被核算用过的单价不许改金额。一个月只能有一份**已确认**核算单（部分唯一索引兜底），要改只能作废重开并写理由。计件金额**不直接发钱**：确认后由工资单带入 `piece_wage` 列，与社保个税一起走正常流程；工资单已确认/已发放导致钱没进单时，`generate` 会返回 `warnings` 点名 —— 不报出来就是静默丢钱。**报工那天人在不在也要管**：「考勤联动」页签里核对报工日期与当日考勤，**考勤明确记了请假/旷工才算冲突**（查不到考勤只提示，计件车间常不打卡，当旷工会误伤），冲突有**三档策略**（只提示照算+确认写说明 / 剔除不计 / 不许确认），另加**单日件数上限**与**缺勤封顶**（月上限 = 日上限 × 出勤天数）；日上限填 0、或整月没有考勤记录时**不封顶** —— 系统不猜车间产能 |
| **扎级完工进度** | 扎标打完、报工记了扎号，但**没人能看出「哪一扎做到了哪一道」**——车间问「B012 车缝完了没」只能翻报工记录，数据攒了用不上等于白记。这一页把每扎走到了哪一道摆成矩阵：行是扎、列是工序、格子里是这一扎在这道工序的合格数。**三条口径写死在服务层**：① **只统计记了扎号的报工**，未归扎的单列汇总、**绝不摊派**（摊派就是编数据，出问题照样查不出谁做的）② **按工序名聚合不按 node_id**（库里有重复工序列 + 跨单脏数据，按 id 分列会把同一道车缝拆两列还漏真数据）③ **完工看末道工序（成品入库），不看「最后一条报工」，且排除「出库发运」**（整单动作，拿它判完工所有扎永远不完）。四状态：完工 / **短数**（末道不足，单独算差几件，短数是钱）/ 在制 / 未开工，外加**超报**独立标记（合格超件数=报工记错扎）。表头带工序序号、状态列带「7/13 道」——否则默认视图藏掉未报工工序后，会误以为整烫之后就直接入库、一片绿就是整条工艺走完 |
| **扎标** | 真正贴到实物上的是**扎标**，不是工单。原来标签只到「订单-款号-色-码」，同一单同色码十几扎打印出来一模一样，**贴上去分不清哪一扎** —— 而车间按扎作业、按扎追溯，断在扎上，返工短数索赔全查不清。扎标含**扎号大字 + 件数 + 二维码 + 订单号 + 款号 + 色/码 + 缸号床次 + 复核状态 + 混缸提醒**；三档尺寸（大 6 张/页、中 12 张/页常用、小 24 张/页），支持**扎号范围补打**（卡纸只补 B008~B014）。三个关键：① **扎号只来自系统**（打印出来对不上系统，比没标签更糟）② **二维码内容「订单号-扎号」纯 ASCII**（中文会让部分扫码枪解不出；第一段是订单号，老扫码逻辑照样认）③ **扫错要能发现**：码里的扎号在这单找不到时手机端弹红条「标签可能印错单，别贴，先核对」。报工可带扎号，记到「这一扎是谁做的」（`production_reports.bundle_no`，**只追溯不参与汇总**，不改任何既有口径） |
| **验货报告** | 照片拍到了、验货单开了，但真正要发给客户时没人会去系统里一张张截图拼 Word。客户要的是一份**能签字的文件**：订单信息 + 款色码 + 尺码配比 + 抽检结果 + 每张检验单的检验项明细 + 不良照片 + 结论 + 签字栏，A4 排版，浏览器「打印 → 另存为 PDF」直接出。**核心是快照**：生成时把整单数据序列化进 `inspection_reports.snapshot`，带编号（`JH`+日期+4 位）与版本号——之后内部再报工、再补照片、再改判定，**已发出去的那份不会变**，客户手里和系统里的永远一致；同单可多次生成，旧版不覆盖。**结论只能来自验货单**（`status='done'` 的最新一张），没有就显示「未验货」并注明「不作为出货依据」，**绝不根据照片推断合格**。预览与生成分两步：`/preview` 实时看（不落库），确认照片齐了再出正式版 |
| **现场照片留证** | 车间与仓库的问题都是**当场看得见、事后说不清**，所以要把「拍一张」做成真会用的动作。手机 `/m/photo` 点「拍一张」**直接调起后置摄像头**（`capture="environment"`，不经过文件管理器）→ 选分类 → 扫单 → 上传；报工抽屉里也能直接拍（提交时报工与照片一起写库）。**必须先压缩**：手机直出 3–8MB，后端上限 4MB、`express.json` 8MB，不压就必然在上传这一步失败——而工人会把「上传失败」理解成「系统坏了」；前端在**选完照片立刻压**（长边 1600 / JPEG 0.82 → 200–400KB，按 EXIF 摆正竖拍，PNG 转 JPEG 先铺白底）。**三条硬规则**：① **不良照片必须写说明**（≥2 字，后端硬拒）——一堆没说明的不良照片三个月后没人看得懂；报工页没填备注时自动用上下文生成「备料不良 2 件」；② **删除是软删除**（照片是证据，物理删了就说不清「当时什么样」）；③ **订单不存在/工序不属于该单不许挂**（历史遗留过孤儿附件）。桌面 `/photos` 照片墙：指标卡（含**不良张数**）+ 近 14 天拍摄量 + 按分类/日期/关键字筛 + 大图看元信息；删除**非 admin 只能删自己拍的**。订单详情附件区改成**图片走缩略图**（看一眼比看文件名有用） |
| **移动端扫码作业** | 车间工人手上只有手机，所以纸质工单上的码要**手机能扫**。单据右上角加**二维码**，内容是扫码直达链接 —— 关键：**地址必须是局域网 IP**（用 127.0.0.1 打印出来的码手机扫了指向手机自己），所以后端提供 `GET /api/settings/lan` 读网卡，同机访问时自动替换。`/s/:code` 扫任何码（订单号 / 标签码 `订单号-款号-色-码` / 输错的码）都进得来，三个大按钮：打开订单 / 快速报工 / 打印工单；**没登录会先登录、登录后自动回到这张单**（`?redirect=`）。`/m` 移动工作台（扫码框 + 四个大按钮 + 最近订单）。`/m/report` **扫码报工**：扫单 → 13 道工序（显示已报数量）→ 点工序弹抽屉填合格/不良/工时 → 提交即时刷新；**首件门禁照旧**（车缝及以后没放行首件会被后端拦并返回原话） |
| **打印单据** | 车间和仓库靠纸干活，所以纸质单据要能用。**生产工单**带**单据条码**（车间扫码报工、仓库扫码入库）、**裁床扎包表**（扎号/颜色/尺码/件数/缸号床次——扎是追溯最小单位，没扎号裁完的扎就跟单对不上）、**工序表带系统报工列**、**现场手写报工栏**（8 行，日期/工序/合格/不良/工时/报工人/班组长）、**车间接收签字**。**装箱单**加箱号/毛重/净重/体积手写列 + 装箱人复核人签字（现场装完才知道箱重，留格子让人写反而准）。**发货单**补收货人/电话/地址/运单号/箱数 + **客户回签**（出问题唯一的凭据）。**批量打印** `/print/batch`：订单列表一键出当前筛选结果（限 50 张），每张独立分页；批量版是精简版，完整工艺单走单张。排版上**跨页表头重复**、手写行高 26–30px |
| **培训手册** | 系统做完了人不会用等于没做。按**岗位**分 7 册（销售 / 技术 / 生产 / 仓库 / 财务 / 人事 / 管理员），每册都是「你每天做什么 → 关键操作分步 → **为什么有些按钮点不了** → 出错怎么查」。图**不是手工截的**：`gen-manual-shots.js` 用各岗位自己的账号登录逐页截图（图里就是这个人真实看到的菜单），界面改了重跑一条命令就更新。另有一份**新人上手演练清单**（每岗 6–8 个任务 + 验收标准）—— 视频只能看，清单必须做。产出单文件 HTML 合订本（8MB，图片内嵌，拷 U 盘就能发、可打印/存 PDF，打印时按册分页） |
| **备份与恢复** | 备份的价值只在恢复那一刻体现，所以这一页测的是**能不能恢复**，不是「能不能下载」。**服务端留档**：每份备份记录编号/sha256/表数/关键表行数/校验结论/耗时，落盘 `data/backups/`，不依赖浏览器有没有点下载。**恢复三步，每步都能反悔**：① **准备**（校验 `integrity_check` + 关键表 + 非空库 → 不过直接拒，绝不把坏文件盖上去 → **先自动备份当前库**做回滚点 → 写待恢复文件）② **撤销**（重启前随时反悔）③ **重启生效**（启动时再校验一次 → 旧库改名到 `data/replaced/` 不删 → **删 `-wal`/`-shm`**（不删会把旧事务重放到新库上）→ 换文件；校验不过就放弃恢复继续用旧库）。**上传走二进制**（base64 会让 11MB 的库撞 8MB 上限，直接 413）。**演练报告自动生成** `docs/DRILL-REPORT.md`：15 张关键表「备份时点 / 写入标记后 / 恢复后」三列对比 + 留档 + 数据健康。**数据健康 6 项**（已过账借贷平衡 / 孤儿分录 / 成品与原料库存对流水 / 孤儿明细 / 账号唯一）**明确不参与恢复判定**——库里本来有脏数据时它照样报，拿它当判据会误判「恢复失败」 |
| **分公司经营对比** | 回答一个问题：**剔掉内部交易、统一口径之后，哪家真正在赚钱、跟上期比好还是差**。**内部收入只按往来单位认**（收入科目上 `partner_name` 命中该主体内部往来单位的部分）；**认不出就不给对外收入**——配了客户类内部往来、本期也确记了对集团内应收、但收入零命中，就把 `external_income` 置空，绝不拿「收入 − 0」冒充对外收入（没配的只提示可能漏配，纯采购主体本来就没有内部收入）。**合并数 ≠ 分部之和**，差额必须对得上已识别内部收入，对不上就报差异、不抹平。**未关账的主体不参与排名**，**没凭证 ≠ 业绩为 0**（单独提示本期只有几家有数）。**环比没有同口径基数就显示「—」**，不拿 0 当分母；**人均用生效任职数，没人数的显示「—」**不编 0。**不二次折算汇率**（凭证入账已是本币）。可比口径调整（一次性损益 / 总部费用分摊 / 汇率影响）**只影响「可比净利」不改账**——所以已关账期间漏记的成本用调整补提，而不是补凭证（补凭证会让权益与损益对不上、合并表直接不平）。报告快照**确认即冻结**，**有硬口径问题不许确认** |
| **税负测算** | **税率不写死**：按「主体 × 税区 × 税种 × 生效期间」配，**没配就不许测算**，绝不用 13% 默认值；改税率是「新增 + 旧记录标已替代」，历史批次带**当时税率快照**。**销项按不含税收入、进项按含税票据换算**（方向搞反差一倍）；应纳增值税为负记**留抵不是退税**；**附加税以应纳增值税为基数不是销项**；所得税亏损为 0；出口退税免抵退取小。确认只是内部确认，**测算 ≠ 已申报**，导出的是申报底稿 | 
| 操作日志 | 所有写操作留痕（账号/方法/路径/状态/IP），仅管理员 |
| 审批流配置 | 管理员按金额区间配置多级审批步骤 |
| 系统 | 汇率设置、图片上传、数据库备份下载 + **上传恢复（重启生效）**、业务蓝图（原思维导图） |
