# 样衣以图搜款

## 简易版

在「技术开发 → 样衣管理」点击「上传图片搜款」，选择 JPG、PNG 或 WebP 图片（最大 3MB）。
系统在当前搜索词和状态范围内查找有图片的样衣，最多显示前 50 款，按相似度排序；点击「查看」打开原样衣。
首次遇到样衣图片时自动建立索引，以后复用；图片变化后自动重新计算。
「返回全部样衣」恢复普通列表。相似度仅用于选款参考，不能替代客户确认或技术审核。
岗位权限管理中，可单独勾选「样衣管理 → 样衣以图搜款」。有列表权限不等于有图搜按钮权限。

## 完整版

### 安装与部署

沿用本项目 Node + Express + Vue 技术栈，安装 `@huggingface/transformers` 与 `sharp`，使用本机 CPU 的 CLIP 图像特征模型。
在 backend 中执行：

```powershell
npm ci
npm run ai:image:install
```

官方模型站点无法连接时，可在安装阶段指定下载镜像：

```powershell
$env:AI_MODEL_DOWNLOAD_HOST='https://hf-mirror.com/'
npm run ai:image:install
Remove-Item Env:AI_MODEL_DOWNLOAD_HOST
```

模型固定为 `Xenova/clip-vit-base-patch32`，revision `6b7c523703ae26e39be4b03774966f8571c7f523`，q8 视觉权重约 89MB。
正式检索禁止远程模型请求；查询图片不落盘、不发送第三方，不需要 AI API 密钥、微信配置或额外收费接口。
模型目录 `backend/data/ai-models/`，派生特征目录 `backend/data/image-vectors/`，均不进入 Git。
新机器部署需重新安装模型或完整迁移模型目录，确认后台服务运行账号有读取模型及读写特征缓存的权限。
前端执行 `npm run build` 后重启后端，以 `/api/health.code_stamp` 确认新代码加载。

### 接口与数据流

1. `POST /api/sample-archives/image-search`，登录且有相应岗位动作权限。
   入参 `{dataUrl, q?, status?}`，返回 `{id,state,done,total,skipped,matches,model}`。
2. `GET /api/sample-archives/image-search/:jobId` 轮询进度，只有提交人可读取。
   状态 `queued → running → done / error`，完成结果带样衣基础字段及 `similarity`（0–100，余弦相似度指标，并非概率）。
3. 候选及最终结果均重新检查当前账号的公司范围；换图或删除的旧结果自动移除。
4. 查询图与样衣图片经同一模型标准化成 512 维向量，以余弦相似度排序。派生缓存键包含模型版本和图片内容 SHA256。

不改业务表结构，不修改样衣冻结快照、打版状态、单号、财务或库存；此功能不涉及业务落库事务。
缓存使用临时文件后原子改名；损坏缓存重建。模型错误明确报错，不用哈希相似度假冒 AI 结果。

### 边界与运行限制

- 支持已有上传区的 JPG/PNG/WebP 图片；远程图片、GIF、缺失文件和损坏图片不计入有效结果，页面显示跳过数量。
- 拒绝外部 URL、目录穿越、符号链接逃逸、非图片字节、3MB 以上或 2400 万像素以上图片。
- 独立子进程推理，CPU 两线程；同一账号只能有一个进行中的任务，全局最多四个排队/运行任务。
- 模型单次处理超过 90 秒将终止工作进程并返回错误，可重试；后端重启后任务失效，请重新上传。
- 完成任务保留 15 分钟、最多 100 个；任务提交日志只记录操作者、任务号和候选数量，不记录图片内容。
- 没有带图样衣时显示空结果；不补造业务档案。查询范围按主图片检索，一款一条，不检索所有细节图。
- 本机通用 CLIP 模型尚未针对本企业服装样本微调；颜色、拍摄背景、角度会影响排序，需由业务判断。
