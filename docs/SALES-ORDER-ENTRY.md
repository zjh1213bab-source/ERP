# 销售订单下单工作台（2026-11-03）

## 简易版

进入「销售订单 → 新建订单」，以全屏表单录入基础信息、多个商品、颜色尺码数量、面辅料和其他信息。布局以本次提供的五张参考图为依据，使用蓝色操作按钮、紧凑表格、固定顶部和底部金额栏。

- 客户选择后自动带出收货人、电话和地址，可展开「收货信息」按本单调整。
- 物料从物料档案选择，主料/里布/配布分别加入；替换、复制、移动只作用于本单。
- 规格、单位、幅宽、克重、空差、供应商由档案带出，业务不能覆盖。成分可以按本单编辑，不回写档案。
- 颜色/色号本单填写，不继承档案颜色。颜色图片和款式效果图、细节图支持系统图片上传与粘贴。
- 颜色尺码数量矩阵支持行复制、列复制、分格价格、尺码模板和客户尺码。库存参考只作展示，保存订单不扣库存。
- 每 60 秒保存当前账号的服务器草稿；明确关闭时也保存。遮罩和空白区域不关闭弹窗。
- 约定定金只记录付款约定，不生成收款凭据，不代表已收款。
- 本厂/外发由生产分单决定；业务录入工序要求时不选择执行方式。

## 完整版：接口与数据流

原入口 `POST /api/orders` 保留。新工作台发送 `entry_version:1`，订单基础数据、款式、尺码、图片快照、面辅料、配色和附件在同一事务保存。任何写入失败全部回滚。

| 接口 | 用途 |
|---|---|
| GET /api/orders/entry/draft?scope_key=new | 读取当前账号当前主体的未提交草稿及版本 |
| PUT /api/orders/entry/draft | `{scope_key,version,payload}`，CAS 保存，冲突返回 409 |
| GET /api/orders/entry/salespeople | 业务员选择，仅返回账号 id 和显示名称 |
| GET /api/orders/entry/product-materials/:productId | 明确关联到已确认开发单的商品辅料，禁止模糊名称猜测 |
| GET/POST /api/orders/entry/material-templates | 当前账号当前主体的辅料模板 |
| POST /api/orders | 新协议包含 request_no、draft_version、items、tags、优惠/附加/定金等；返回完整订单 |

新协议保存仍只依赖「新增订单」操作权限，自动保存不要求额外的草稿权限。权限来源仍是 `src/access/permissions.js`。原接口、旧订单及其历史金额口径不变。

### 表结构与并发

- `orders.entry_json`：商品额、税额、运费、优惠、附加、约定定金、尾款、标签快照。
- `order_items.entry_json`：本款税率、输入币种、颜色图片、客户尺码与工艺要求快照。
- `order_materials.entry_json`：分组、使用部位、档案空差、分色单价/图片、分码用量。
- `order_entry_drafts`：账号、主体、业务范围、请求编号、状态、版本、内容、订单关联与时间。正式提交后同事务置为 submitted，过期自动保存不能把已提交草稿恢复成未提交。
- 主档选料带 `archive_version`。档案变化时返回 409，要求重新读取档案；服务器重新查询真实规格、供应商和空差。
- 请求编号及摘要防止网络超时后的重复提交。相同请求返回原订单，不同内容复用已提交编号返回 409。最终仍受手填单号唯一校验保护。
- 所有结构在 schema.js 定义，旧库启动由 db.js 补列；新增父子关系已登记数据审计。

### 金额和用量

新协议以 USD 为订单结算币种。人民币商品输入由服务器按系统汇率换算，客户端不得修改系统汇率。每个尺码行先四舍五入至两位，再累计至款和订单。

`应付总额 = 商品合计 + 逐款税额 + 运费 + 附加金额 − 优惠金额`。

优惠不得使应付为负，约定定金不得高于应付。旧协议不会自动改变运费计入口径。草稿二次编辑共用结算函数，并保持款式主键，防止关联物料成为孤儿。

物料用量和金额统一由 `orderMaterialColors.recalc()` 计算：每个有效尺码格的件数 × 单件用量 × (1+损耗/100) × 100/档案空差；分码用量优先，其次分色用量，最后为物料基础用量。分色单价未填写时沿用基础单价。

商品「一键同步辅料」仅复用有明确商品关联、状态已确认的开发单中仍有效的档案物料。没有 BOM 时提示选择档案，不生成虚构物料。辅料模板使用时重新读取主档，停用物料会被拒绝。
