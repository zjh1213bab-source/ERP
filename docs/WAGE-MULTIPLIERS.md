# 工价倍率（简易版）

系统设置 → 工价倍率。默认：同款同色1件3倍、2–5件2.16倍、6–10件1.8倍、11–19件1.44倍、20件及以上1.2倍。支持调整连续档位与倍率，最后一档上限留空；关闭后新报工按1倍计算。

数量口径：同一订单、同一款号、同一颜色，跨尺码合计，不按本次报工或扎数量。无款号时仅按该款式明细行识别，不猜不同款式相同。

员工从“我的自助 → 扫码计件报工”进入；账号须绑定在职员工。选择工序和款色后显示基础工价 × 倍率 = 最终单价，如0.4 × 1.2 = 0.48。基础价来自计件单价维护，缺价显示待维护，不按零发工资。

## 完整版：接口与数据

GET/PUT /api/settings/piece-multipliers 使用 app_config 独立键 piece_wage_multipliers_v1，与汇率、外观分开；revision 防覆盖，事务保留修改前后、操作人及时间。首次未保存使用默认档位。更新仅影响新报工。

管理端 /api/reports/wage-quote 与员工 /api/self/work-quote、/api/self/work-report 共用 services/wageMultiplier.js。员工只获得订单基础信息、工序和汇总，报工强制归属账号绑定员工，忽略客户端伪造的员工、姓名、基础价和倍率；主体、订单状态、首件、技能门槛继续生效。

新增列：production_reports.wage_snapshot / request_no / request_hash，piece_wage_items.wage_snapshot；新增幂等唯一索引 uq_production_report_request。schema.js 和 db.js 同步维护，无新增业务表。

快照含款色、颜色总件数、档位、配置版本、基础价、倍率和最终价。报工、快照与工序状态同事务写入，失败全回滚。报价后设置改变返回409，需刷新工价。颜色累计报工和整单累计均不得超量。request_no 重试返回原记录，改内容复用编号返回409，事务内二次检查防并发。单价保留6位、金额保留2位，不把0.864提前改成0.86。

月度计件使用报工快照并保存核算明细；之后修改设置或基础价不改变已有报价。缺价报工锁定倍率，补齐适用基础价后才可核算，仍保留缺价诊断。历史无快照不追溯加倍，已确认核算不重算。

## 参与工序范围

设置中可选“全部工序参与”或“仅勾选工序参与”。后者支持车缝、印花、绣花、洗水、后整、包装、其他七类，也可单独选择生产流程工序或工序类别档案。选择类别包含其所属全部工序，多个选择取并集；全部不选表示没有工序参与，按1倍基础价计算。关闭全局倍率同样按1倍。

范围存入同一配置的 process_scope，字段为 mode、categories、craft_type_ids、node_codes，与档位共用 revision、事务和审计记录，不改表。读取老配置缺省为全部参与，升级不擅自修改当前员工工价。首次限制范围需管理员在设置中勾选并保存。

内置生产工序按稳定 code 归类，改显示名不改变类别。自定义工序按工序档案唯一同名对应，无法明确归类时不套用倍率，扫码显示未归类说明；同名多类别不能猜。单独选择生产流程工序可避免依赖显示名。已停用档案保留原选择，不能新增勾选停用工序。

扫码报价和报工快照增加 participates、process_category、matched_craft_type_id、scope_mode、participation_reason。员工可看到是否参与和1倍原因。月底继续按报工保存的倍率计价，之后更改参与范围不改变历史工价。范围校验、报价、报工和核算共用服务参与判定，客户端传入的工序类别不作为依据。
