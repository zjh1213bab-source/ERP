# 客户确认数据链路与操作说明

## 简易版

1. 预下单按款录入客户要求及图片，寻样申请必须选择具体款式。
2. 采购回传候选，业务确认可用，技术完成打版准入审核，生成开发单与打版流程。
3. 打版全部阶段完成并成功归档后，样衣库保留锁定快照。归档失败，流程完成状态一起回滚。
4. 预下单转正式订单时，按来源款式 ID 续接开发单、打版、样衣及新品开发申请。
5. 客户确认页面选择正式订单、具体款式、样衣版本，创建封样。旧资料未明确款式时可选择开发单并“关联到本款”。
6. 技术批准后发给客户商城，客户确认或拒绝。定制单所有款式最新封样均须通过，才可通过订单技术确认的封样门槛。
7. 需要变更时选择真实明细与新值，提交影响评估。统一审批全部通过 → 客户确认 → 生产工位签收 → 应用实际修改并留痕。

## 完整版：关联关系

| 来源 | 目标 | 关联依据及行为 |
|---|---|---|
| 预下单款式 | 新品开发申请／开发单 | `pre_order_item_id`，防止多款串单 |
| 正式订单款式 | 开发单 | `order_item_id`；转单按预下单款式 ID 对应，旧数据仅在唯一匹配时自动关联 |
| 开发单 | 打版／样衣库 | `tech_pack_id`；归档锁定原始快照 |
| 封样 | 订单款式／样衣版本 | `order_item_id`、`archive_id`、`snapshot_json`、内容校验值 |
| 变更 | 统一审批 | `approval_instances.target_type='order_change'`，实例保留步骤快照 |
| 客户商城 | 封样／变更／交期 | 客户账号仅能操作自己客户的订单，记录确认人、意见及时间 |
| 生产签收 | 订单实际业务明细 | 应用已批准的结构化变更，保存前后内容、操作人及时间 |
| 交期确认 | 订单最新预计交期 | 更新 `latest_delivery_date`，原 `delivery_date` 不变 |
| 物流集成／人工登记 | 客户物流视图 | 共用 `shipment_events`，保留来源及核实状态 |

### 实际应用的变更范围

- 工艺：本订单工艺明细的执行说明、备注。
- 面辅料：本订单成分、颜色／色号、备注；可从同类型启用主档替换物料，规格、单位、供应商从档案带入。不会反向修改主档或历史样衣。
- 数量：指定颜色尺码行数量，重新汇总款式数量、订单金额、物料用量。
- 价格：指定颜色尺码行美元单价，重新汇总美元和人民币金额。
- 交期：写最新预计日期，保留原承诺日期及延期确认记录。

数量与价格仅在分单生产前应用，必须包含财务审批；应用后成本单退回草稿，旧成本审批失效，需要重新测算审核。
已有交付的非交期变更须先拆分剩余订单，不允许整单覆盖已交付历史。
物料／工艺信息的变更不自动产生收付款、库存调账或供应商结算。

### 状态、并发与失败处理

- 封样：草稿 → 技术批准 → 发样待确认 → 客户确认／拒绝；新版本只替代同款旧版本。
- 样衣库有新版，或者封样绑定的款图、物料规格、工艺说明变化时，旧封样不能继续放行。
- 变更：草稿／评估中 → 统一审批 → 待客户确认 → 待工位签收 → 已应用生效。
- `row_version` 防止旧页面覆盖；生效时再次比较目标快照及引用档案，冲突会拒绝，并保持原数据。
- 统一审批任务与业务回写使用同一保存点；回写失败，不会出现“任务已批准、业务未生效”。
- 签收、实际应用、金额汇总及操作日志在同一事务；任一步失败全部回滚。
- 已关联开发的预下单款式编辑保留 ID，不允许直接删除造成断链。
- 数据范围按订单所属公司校验，列表、统计与详情门槛同样受控。
