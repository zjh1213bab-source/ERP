# 业务交版及改版许可

业务在开发详情保存物料、外发工艺和客户要求后，点击“保存并提交打版”。至少需要物料和客户要求；无外发工艺可留空。交版后资料锁定。

再次修改：开发详情“申请修改资料”填写原因 → 打版流程内技术/版房审核 → 批准时版本递增（V1→V2），原申请人可编辑 → 保存后自动待复核 → 技术复核通过恢复流程。驳回申请不开放编辑；复核不通过恢复修改前物料、工艺及客户要求，保留已产生的版本标识和审核记录。修改期间打版保存、完成和归档均暂停。

已完成归档的样衣仍需使用样衣管理变更流程，本入口不会解锁已归档样衣。历史“已确认”开发单按已交版处理，进行中的资料可申请改版，避免直接解锁。

后端：tech_packs 新增 business_submitted_at（schema.js + db.js幂等迁移）。沿用 pattern_change_requests 保存原资料快照、原因、申请人、审批及复核记录，新增 development_revision 类型和 editing 状态。版本变更与审批同事务；修改保存与进入待复核同事务；驳回复核与快照恢复同事务。保存检查 updated_at，旧版本返回409，旧通用编辑接口拒绝已交版资料。

接口：POST /api/techpacks/:id/submit-development、POST /api/techpacks/:id/request-development-change；审批/复核复用 pattern-flows/changes 接口。无额外外部参数。生产重载前在线备份，重载后核对 health.code_stamp。
