# 采购工作台与分配订单

## 简易说明

侧栏新增“采购”分组，包含“采购列表”和“分配订单”。原生产菜单不再重复放分配入口，原仓储菜单不再重复放采购列表。原URL保持有效，岗位权限不因菜单移动而提升。

采购页参照截图采用三列订单卡片、上方两行组合筛选与单行分页，提供按订单采购 / 物料清单 / 采购明细 / 回料明细四个页签。支持9/18/36/72条、图片放大、新增采购、草稿选择批量确认下单、实际采购明细、留言及采购单打印，兼容深浅主题。

## 完整业务口径

- GET `/api/purchases/workspace`：按主体读取订单、采购单及子行、最新技术版物料、分单工厂、颜色尺码、收料检验事实。GET不重算齐套、不修改订单或库存。
- 采购员当前按采购建单人展示，未建单显示“—”；不是自动指定新负责人。加工厂取已有分单，未分配不冒充本厂。
- 物料需求参考来自最新技术资料和对应款/颜色数量；用量未维护或多色不能准确对应时显示“—”，不推断需求。手动采购仍从档案选择并由采购确认数量。
- 面/辅料状态分别由有效采购明细及点收数量计算。已到货不等于可用库存，来料检验及原有库存闸门保持不变。
- 没有对应物料资料显示“未登记”；已登记但未建单显示“待采购”。备货采购单没有关联销售订单时保留独立卡片，不能遗漏。
- 本项目现有采购没有独立审批状态机，因此不虚构截图中的“已通过”。审核筛选明确为“按现有流程直接下单”；批量按钮执行真实的“批量确认下单”，不是空的“批量提交审核”。本次未新增审批门槛、未改审核策略。
- 批量确认复用原POST `/:id/order`。逐张处理并展示成功/失败，成功单不重复下单，失败草稿保留。
- POST `/:id/note`：备注追加，2000字限制，带操作人/UTC时间，使用updated_at乐观锁避免覆盖他人留言；必须有采购写入及岗位note操作权限，主体校验沿用采购单守卫。
- 打印 `/print/purchase/:id` 支持同一订单关联多张采购单逐页打印，使用真实供应商/数量/金额及备注，打印不包含节日背景。
- 回料明细点击实际收料单，跳转原料收货检验并打开该单；没有模块读取权限时隐藏操作。
- 查询上限5000张订单/采购单，触顶明确提示；明细与数据均限定到可见父单，不泄露另一主体信息。
