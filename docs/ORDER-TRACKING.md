# 订单跟踪（参考生产订单布局）

## 简易说明

入口：生产 → 订单跟踪（`/order-tracking`）。采用组合筛选、交期横条、分类页签、订单缩略图与横向节点流程。支持列表 / 卡片 / 进度表格、同款汇总、当前页打印、12 / 24 / 48 / 96 条分页。

点击交期或超期卡片即时筛选下方列表；点击节点或“沟通”进入真实节点面板。明确按钮关闭弹窗，遮罩点击不关闭。显示颜色跟随工作空间深浅主题，业务状态色保持区分。

## 完整口径与接口

复用 GET `/api/node-flow/board`。新增可选查询：tracking=1、po / po_mode、style、batch（最多100项精确编号）、communication、completed_from / completed_to、order_type、no_nodes、out_craft、sort_dir；原节点看板参数保持兼容。

- PO搜索匹配系统订单号 / 客户订单号；款号搜索匹配订单款名及商品行款号 / 名称，批量搜索匹配完整编号。
- 完成时间指发货节点（ship）实际完成时间，并非随意取订单更新时间。
- 外发工艺筛选来自 order_crafts.is_out；无工序筛选来自 order_nodes 不存在，不再错误绑定“未填货期”。
- 全部跟踪包含待分配、已分单、生产中、已入库、已发货、已结案及作废；跨模板按每单自身模板展示工序。
- 本厂 / 整单外发 / 裁片外发按有效分单事实判断，未指定厂不冒充已经分配。
- 次品返修来自未结/未驳回 rework_orders；订单异常来自未关闭 exception_items；成本管控异常本次明确为 cost_sheets 审核驳回，不推断财务余额异常。
- 交期卡片按当前后端筛选结果聚合款 / 单 / 件；超期率分母为有货期且未交付/作废的订单，分母不足5显示“—”。超过5000单明确提示缩小查询范围，防止把截断数据当全量。
- 节点数量进度只计算该节点合格报工 / 整单件数，显示封顶100%；全流程完成率保留原服务口径，隐含扫码步骤仍计入。
- 在库数为订单关联库存流水净额；未登记显示账面0，不伪造实物记录。同款汇总以整单款式组合分组，避免多款订单金额/数量重复计入。
- 主体过滤在SQL查询前执行；不新增写接口或放宽订单、入库、发货状态机。
- 没有可用的参考操作视频，使用实际操作说明；打印、详情、节点、异常均有实际入口。

## 数据和部署

无表结构变更、无新配置参数。前端 npm run build；后端变更加载后核对 /api/health 的 code_stamp。测试只写临时 __SMOKE.db，不修改在用订单，不清理用户要求保留的实测记录。

## 2026-11-05：分配模块与生产显示分流

- 独立菜单“分配订单”：`/order-allocation`，包含待分配、已分配本厂及整单外发记录；复用共享跟踪组件，不复制一套业务逻辑。
- 只读接口 `/api/dispatch/board` 强制 assignment 范围；`/api/dispatch/:orderId/context` 校验订单主体后给出已有分配、剩余数量及启用工厂选项。权限沿用分单模块 read / create。
- 实际分配走原 POST `/api/dispatch` → orderAssign.addDispatch，财务成本审核、数量上限、事务及覆盖整单后转 assigned 保持不变；停用工厂禁止分配。没有启用本厂档案时可明确选择“本厂（内部生产）”，以既有手工承接方字段记录“本厂”，不自动创建工厂档案。
- 订单跟踪 `/order-tracking` 仅显示分配本厂或实际已发出裁片的订单；纯整单外发及未分配订单移到分配模块，SQL先过滤再统计/分页。部分本厂+部分整单外发保留本厂视图。
- 裁片外发只认 sent/partial/returned/closed，草稿及取消记录不改变车缝；车缝显示“外发至 工厂名”，多承接厂全部列出。
- 纯整单外发按稳定 code=iron 从尾整节点及其后序开始展示；模板缺少iron时仅展示已知收尾节点。仅改变展示，原节点、进度计算、报工、库存闸门及历史均保留。
- 本次无表结构和配置项变更，用户保留实测记录不删除、不迁移。
